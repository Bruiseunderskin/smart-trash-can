## 0. 決定

| 項目 | 決定 | 理由 |
|---|---|---|
| 節點 ↔ S31 連線 | **USB CDC（有線）** | demo latency 可預期、無頻道問題、一條線供電＋數據 |
| 節點板 | **Seeed XIAO ESP32-C5** | 已有；原生 USB-Serial/JTAG；11 GPIO |
| 舵機驅動 | **PCA9685**（16 路 12-bit PWM，I²C） | 硬件波形、無 jitter、唔食 CPU |
| 數位輸入 | **TCA9555**（16 位 I²C，帶 INT） | 上拉強、支援中斷、螺絲端子免焊 |
| 無線備選 | ESP-NOW（同一份 firmware，config flag 切換） | 協定與傳輸層解耦，換傳輸不改邏輯 |

S31 側不需要任何 GPIO：只用它的 USB-A Host 口。

11 條排針 GPIO 全部列出，本方案只用 3 條，剩 8 條。

PCA9685 地址 0x40（可跳線改），TCA9555 地址 0x20–0x27。

感測器分配：

| TCA9555 bit | 訊號 | 觸發 |
|---|---|---|
| P0–P3 | 桶 0–3 槽型光電 | 有物穿越 = LOW，去抖 5–10 ms |
| P4–P7 | 桶 0–3 蓋位磁簧 | 蓋關 = LOW，去抖 30–50 ms |

PCA9685 通道：

| 通道 | 用途 |
|---|---|
| CH0–CH3 | 桶 0–3 蓋舵機 |
| CH4–CH15 | 備用 |

## 3. 幀格式（16 bytes，little-endian）

節點 → S31：

```
off  size  field
0    1     magic   = 0xA7
1    1     version = 0x01
2    1     type    (1=LID_OPEN 2=LID_CLOSE 3=CARD_PASSED 4=HEARTBEAT 5=ACK 6=OFFLINE_NOTICE)
3    1     bin_id  (0–3；不相關用 0xFF)
4    4     seq     uint32
8    4     t_us    uint32  節點單調時鐘（µs），事件發生時刻
12   2     arg     uint16  例如舵機角度、延遲回報編號
14   1     flags   bit0=重播(來自緩衝) bit1=低電量 bit2..7 保留
15   1     crc8    poly 0x07，覆蓋 byte 0–14
```

S31 → 節點（type | 0x80）：

| 值 | 指令 | arg |
|---|---|---|
| 0x81 | CMD_OPEN_LID | bin_id，arg = 角度 |
| 0x82 | CMD_CLOSE_LID | bin_id，arg = 角度 |
| 0x83 | CMD_SET_ANGLE | arg = 角度（配合 bin_id） |
| 0x84 | CMD_SESSION | arg = 1 開始／0 結束 |
| 0x85 | CMD_CALIB | arg = 1 進入學習模式 |
| 0x86 | CMD_PING | — |

規則：
- 事件驅動，不輪詢；心跳每 200 ms 一次
- 節點保留 **16 個事件的環形緩衝**；USB 斷線重連後，將未確認事件以 `flags.bit0=1` 重播，保留原始 `t_us`
- 收到 CRC 錯 → 丟棄並計數；S31 連續 5 個錯幀即視為節點故障
- 任何情況 S31 都不得在缺 `CARD_PASSED` 的情況下給分

## 4. 延遲預算（設計目標，**必須實測取代**）

| 環節 | 估算 | 可調？ |
|---|---|---|
| 槽型光電邊沿 + 去抖 | 5–10 ms | 可（10 ms 足夠，訊號乾淨） |
| 磁簧去抖 | 30–50 ms | 可（唔影響 demo 觀感） |
| 節點 → USB 送出 | <1 ms | — |
| USB CDC 傳輸（1 ms 幀間隔） | 1–5 ms | — |
| S31 解析 + 狀態機 | <1 ms | — |
| I²C 寫 PCA9685（400 kHz，4 bytes） | ~0.2 ms | — |
| 舵機 0°→90°（MG90S，4.8 V，0.1 s/60°） | ~150 ms | 可（換 6 V 或短行程） |
| 蓋子機械行程 | 50–150 ms | 可（機構設計） |
| **感測 → 蓋開（合計）** | **≈ 200–320 ms** | |

對比 M3 驗收門檻 3 s，餘量約 10 倍。AI 分類 p95 84 ms 另計。

### 4.1 量測方法（不需要兩塊板共用時鐘）

1. **節點自測**：中斷入面記 `t_edge`，寫入 USB 前記 `t_tx`，同一幀內另送 `t_tx` → 得「邊沿→送出」延遲。
2. **S31 自測**：由收到整幀到寫入 I²C 指令的耗時 → 得「主機處理」延遲。
3. **舵機＋機械**：節點記 `t_cmd_recv`（收到 CMD_OPEN_LID）與 `t_reed_release`（同一顆磁簧由 LOW 變 HIGH，即蓋真的離開）→ **同一塊板的同一個時鐘**，量到的是真正端到端機械延遲，無需時鐘同步。
4. 三項相加即完整鏈路；每項各取 50 個樣本，報 p50 / p95，寫入報告。

## 5. 上電與初始化次序（避免舵機抽搐）

1. XIAO 開機 → 先把 PCA9685 `OE` 腳拉高（輸出關閉）
2. I²C 初始化（400 kHz）→ 確認 0x40 與 0x20 有 ACK
3. 由 NVS 讀取四隻蓋的角度 → 寫入 PCA9685（PRE_SCALE = 121 → 50 Hz）
4. 設 `OE` 低（放開輸出）
5. 開始送心跳；等 S31 的 `CMD_SESSION`

若第 2 步任何一個地址無 ACK → 節點進入 `FAULT`，LED 紅快閃，送 `OFFLINE_NOTICE`，**不假裝正常**。

## 6. 失敗處理

| 情境 | 節點 | S31 |
|---|---|---|
| USB 斷線 | 事件入緩衝，持續嘗試重連 | 顯示「感測器未連接」，鎖住計分 |
| 重連 | 重播緩衝事件（`flags.bit0=1`） | 依 `t_us` 排序，過期事件（>5 s）僅記錄不計分 |
| 心跳連續 3 次缺席（600 ms） | — | 標記節點離線，畫面提示 |
| 磁簧與指令不一致（叫開但 2 s 未開） | 送 `OFFLINE_NOTICE`（機構卡住） | 提示「蓋子被卡住」，不計分 |
| 光電無訊號但蓋已關 | 仍送 `LID_CLOSE` | 判定「未真正投放」，該回合 0 分 |

## 7. 驗收測試（要交數字）

1. **偵測正確率**：4 桶 × 20 次投放（卡紙／皺紙／薄膠袋各若干）→ 漏檢 0、誤檢 0
2. **抗粗暴**：每桶連續拍蓋 100 次 → 不得產生 false `CARD_PASSED`
3. **斷線韌性**：投放中途拔 USB，5 s 內插回 → 事件不遺失、回合可繼續
4. **延遲**：§4.1 三項各 50 樣本，列出 p50 / p95
5. **連續運行**：30 分鐘不間斷操作 → 無掉幀、無記憶體增長
6. **冷啟動**：上電到可接受指令 ≤ 2 s；期間舵機不得抽動
