## 1. 硬件與接線

### 1.1 Korvo-1（S31）

- 相機 SC101IOT（1280×720，DVP 8-bit，YCbCr422）；**每回合只抓一幀**
- 4.3″ 800×480 RGB LCD（LVGL）
- 按鍵：用板上 ADC 四鍵的 **PLAY** 作「掃描／下一張」實體觸發（GPIO42，免額外接線）
- 音頻：ES8389 codec；短句預錄放 flash，SD 卡作第二來源（見 §8）

### 1.2 S3-DevKitC-1

| 功能 | GPIO | 備註 |
|---|---|---|
| 舵機 CH0–CH3 | 4, 5, 6, 7 | LEDC 50 Hz；開／關脈寬各留 ≥50 µs 機械餘量 |
| I²C SDA / SCL | 8 / 9 | 400 kHz |
| XSHUT ×4 | 10, 11, 12, 13 | 每條 **10 kΩ 下拉到 GND** |

避開：0／3／45／46（strapping）、19／20（USB）、33–37（Octal PSRAM）。

### 1.3 電源

- 舵機：獨立 5V **3A**，每顆舵機並 470 µF
- `OPEN_ALL` 改 **錯開開啟**：桶 0→1→2→3，間隔 80–120 ms（降低突入電流與機械衝擊）
- 共地：S31、DevKitC、5V PSU 三方 GND 必須連通；舵機回流線直接回 PSU，不經 DevKitC 排針
- ToF 與 DevKitC 由 DevKitC 的 3V3 供電，**不與舵機共用 5V rail**

## 2. 遊戲規則（唯一讀法）

1. 卡池 30 張，全賽程不重複發放。
2. 每局 **5 回合**；每回合由卡池抽 **1 張**（已用過的卡不再出現）。
3. 回合流程：玩家按 PLAY → 抓拍分類 → 四個蓋打開 → 玩家把卡投入任一桶 → 系統判定 → 顯示答案 → 關蓋 → 下一回合。
4. 計分：投入的桶 == 模型 label → +10；≠ → −5；15 s 內無投入 → 0 且關蓋。
5. 每回合**關一次蓋**（不是每張卡關一次）。
6. 5 回合後結算；分數存 NVS，另寫一份到 SD（若掛載成功）。

> 原文「每回合 5–6 張」作廢。原「3 分鐘」不作為硬性計時器；一局實際約 75–100 s，賽制允許時可連跑多局。

## 3. 感測：ToF 幾何與取樣

### 3.1 安裝

- 每支 VL53L0X 裝在**桶身內壁、桶口下 8–15 cm**，光軸**橫切**落卡路徑（不是貼住桶口向下掃）
- 桶與桶之間加隔板或擋光片（FoV 25°，避免互見）
- 感測器加保護窗時，必須做 crosstalk ＋ offset 校正（datasheet 要求）

### 3.2 取樣

- Timing budget **20 ms**（短距模式），四顆輪詢一輪約 88–96 ms
- 不使用「絕對距離門檻」；用**邊緣＋形態**判定：

```
baseline = 最近 10 個樣本的中位數（每 2 s 更新，避開事件窗）
事件條件（三個同時成立）：
  (a) 距離比 baseline 短 ≥ 25 mm
  (b) 連續 ≥ 3 個樣本（≥ 60 ms）
  (c) 之後 500 ms 內回到 baseline ±15 mm
觸發後：該桶記為 candidate，等 (c) 成立才發 CARD_PASSED
```

- 開蓋後 **300 ms 內不判定**（蓋板／手尚未離開）
- 四桶同時 candidate → 取「距離變化最大」者為答案，另一個記入 log 作 debug
- 一回合只接受**一次** CARD_PASSED（後續觸發只記錄）

### 3.3 已知失效模式（要寫入報告）

| 模式 | 表現 | 對策 |
|---|---|---|
| 全黑／絨面卡 | 回波弱，距離偏遠或無效 | 實測；必要時在該桶加擋光片 |
| 鏡面覆膜斜角 | 回波消失 | 用啞面過膠卡；實測列入驗收 |
| 手伸入 | 先於卡觸發 | (c) 的回復條件會令手觸發不成立（手離開後距離回復但無「卡」停留）→ 需要人手實測校準，見 G2 |
| 蓋板落於 FoV | 恆定短距 | G1 必須確認蓋全開時不在錐內 |

## 4. 通訊協議 v1（ESP-NOW）

固定 16-byte binary，little-endian：

```
0  magic 0xA7
1  proto 0x01
2  type  (1 OPEN_LID 2 CLOSE_ALL 3 START_MONITOR 4 STOP_MONITOR
         5 DROP 6 TIMEOUT 7 ACK 8 HEARTBEAT 9 GET_STATE 10 STATE)
3  bin   0–3 | 0xFF
4  seq    uint32（每板單調遞增，用於去重與排序）
8  round  uint8
9  card_id uint8（0–255，卡池流水號）
10 t_ms  uint16（相對於該局開始，4 ms 解析度，夠 65 s）
12 arg   uint16（距離 mm／角度／錯誤碼）
14 crc8  poly 0x07
15 flags bit0=重播 bit1=錯誤 bit2..7 保留
```

規則：

- **冪等**：同一 `(seq, type, bin, round, card_id)` 只處理一次；去重窗口 5 s
- **重送**：未收到 ACK 者，300 ms 後重送，最多 3 次；3 次失敗 → 進 `DEGRADED`
- **重同步**：任一板重啟 → 發 `GET_STATE`，對方回 `STATE`（round、分數、蓋狀態、已用 card_id 位圖）
- **心跳**：200 ms；連續 3 次缺席 → 對方標記離線並顯示提示

## 5. 狀態機

```
IDLE
 └─(PLAY 按下)→ CAPTURE           抓一幀，停相機
      ├─(影像可用)→ CLASSIFY       ≤ 1.5 s，超時視為失敗
      │     ├─(信心 ≥ 0.55)→ OPEN_ALL → WAIT_INSERT
      │     └─(信心 < 0.55)→ SCAN_RETRY（最多 2 次）→ 仍失敗 → ROUND_VOID(0 分)
      └─(抓拍失敗)→ SCAN_RETRY
WAIT_INSERT（15 s）
 ├─(CARD_PASSED)→ SETTLE（3 s，TTS 同時播）
 │      └─(TTS 未播完)→ 等 TTS 完（上限 8 s）→ CLOSE_ALL
 └─(15 s 無事件)→ CLOSE_ALL → ROUND_VOID(0 分)
CLOSE_ALL →（等 500 ms）→ NEXT_ROUND 或 GAME_OVER
```

- `ROUND_VOID` 也消耗一張卡（卡池一致）
- 分數在 `SETTLE` 完成時才 commit（避免重啟丟分）
- 任何一板重啟 → 重跑 `GET_STATE`，由 `round` 與已用 card_id 位圖續接

## 6. 影像管線（Korvo-1）

1. 抓一幀 1280×720 YCbCr422 → 直接進 PSRAM（單緩衝即可，因為不串流）
2. **PPA SRM 一次完成**：YUV422_UYVY → RGB565，同時縮放到模型輸入（例如 128×128）
   - 用 BT.601 還是 BT.709 由 SC101IOT 的實際輸出決定 → 用 G3 的一張色卡確認
   - PPA 輸出是 RGB，模型若要求 BGR，在預處理時換 channel order（不要靠 PPA）
3. 模型輸入：**訓練與推論必須用同一條 PPA 管線產生的圖**，否則 train/infer 不一致
4. 模型：int8 為目標（ESP-DL 對 esp32s31 有量化路徑），float32 作基準對照；兩者都量 p50／p95
5. 抓拍後立即停相機，再做推理與 UI → 避開 LCD_CAM 同時驅動相機與 RGB 面板的爭用

## 7. 語音與畫面

- 回合中所有語音為**預錄短句**（開場、答對、答錯、逾時、結算），存 flash；SD 卡有掛載就用 SD，冇就自動回落 flash
- SHOW_INFO 與關蓋的關係：關蓋時間 = max(3 s, TTS 結束)，上限 8 s
- 畫面：分類中（相機預覽）→ 等待投放（四桶狀態）→ 答案（類別說明＋分數）→ 結算

## 8. 錯誤處理與降級

| 情況 | 行為 |
|---|---|
| 某支 ToF 改址失敗 | 該桶標記 `SENSOR_FAULT`，畫面提示；該桶仍可開蓋但投進去只計 0，並在結算頁列出 |
| I²C NACK | 重跑該支改址；連續 3 次失敗 → `SENSOR_FAULT` |
| ESP-NOW 3 次重送失敗 | `DEGRADED`：畫面顯示「連接不穩」，仍可完成本局（事件以本地記錄為準） |
| 相機抓拍失敗 | 重試 2 次；仍失敗 → ROUND_VOID，不計分，提示「請重試」 |
| SD 卡缺失／掛載失敗 | 自動用 flash 語音；分數只存 NVS，結算頁提示 |
| 舵機卡住（無回授，只能事後知） | 該回合 0 分；log 記 `CMD_OPEN`/`CMD_CLOSE` 時間戳，賽後對照 |

## 9. 驗收標準（數字，可證偽）

**G1 幾何閘（開工前）**
四種材質（印刷啞面卡／全黑卡／鏡面卡／皺紙）各 4 次、真實桶口位置：
- 漏檢 ≤ 1/16，誤檢 = 0
- 開蓋全開時，四支 ToF 讀數不得出現「恆定 <100 mm」

**G2 偵測（實作後）**
- 4 桶 × 20 次投放，每材質 5 次：總漏檢 ≤ 1/80、誤檢 = 0
- 手伸入再離開、不投卡：不得產生 CARD_PASSED（20 次測試 0 次誤判）

**G3 延遲**
- 按下 PLAY → 蓋開始動：p95 ≤ 500 ms
- 按下 PLAY → 蓋全開：p95 ≤ 3 s
- ToF 事件 → S31 收到：p95 ≤ 50 ms

**G4 穩定**
- 連續 10 回合（2 局）0 次人工介入（定義：除按 PLAY 與投卡外的任何操作）
- 30 分鐘連續運行：無掉幀、無記憶體增長、無需重啟

**G5 通訊**
- 拔電／重插任一板 → 10 s 內自動重同步，該局可繼續
- 100 次指令：0 次重複執行（冪等驗證）
