## 1. 視覺語言：保留，但收緊成系統

現有配色與語氣（深綠頂欄、奶油底、青檸強調、粵語短句）是這個項目最好的一部分，全部保留。
問題不在風格，在**沒有系統**：字級不統一、元件各自為政、顏色不承載資訊。

### 1.1 Design tokens

| Token | 值 | 用途 |
|---|---|---|
| `ink-deep` | `#14342B` | 頂欄、按鈕、主文字 |
| `paper` | `#F5F3E9` | 畫面底 |
| `card` | `#FFFFFF` | 卡片、格 |
| `lime` | `#DCE45A` | 主行動、答對、強調 |
| `cat-recycle` | `#2F63E8` | 可回收物 |
| `cat-food` | `#2E9E5B` | 廚餘（亦可作「正確」綠） |
| `cat-hazard` | `#C6412F` | 有害／錯誤 |
| `cat-other` | `#7A868D` | 其他 |
| `warn` | `#E0912B` | 提示、需重試 |

### 1.2 字級（800×480）

| 層級 | px | LVGL 字型 | 用途 |
|---|---|---|---|
| Display | 72–112 | `stc_font_tc_112` / `stc_font_num_80` | 類別名、總分；一屏最多一個 |
| H1 | 48 | `stc_font_tc_56` | 每屏指令句 |
| H2 | 32 | `stc_font_tc_32` | 卡片標題、按鈕 |
| Body | 26 | `stc_font_tc_26` | 說明、知識點 |
| Meta | 22 | **需新增** | 回合、時間、錯誤碼 |

> 22 px 是唯一要重新產字的字型。沒有它，「第 2/5 回合」「剩餘 02:41」只能用 26 px，每屏頭重腳輕。

### 1.3 版面骨架（四區，永不跳位）

```
TOPBAR  56 px   左：品牌／回合　右：倒數或分數
BODY   320 px   主內容
ACTION 104 px   按鈕（1–2 顆，高 88 px）
間距    8 px 基準（8／16／24／32）
```

## 2. 現有畫面診斷

| # | 問題 | 現況 | 影響 |
|---|---|---|---|
| 1 | AI 答案太早揭曉 | classifying → result_ok 直接顯示「可回收物」 | 玩家照抄，遊戲不成立；25% AI 分會被問穿 |
| 2 | 蓋由系統控制 | result_ok 寫「等待開蓋，請勿推動桶蓋」 | 與 M1（玩家自己蓋＝投票）矛盾，且無蓋位顯示 |
| 3 | 無回合／無總時間 | 只有「連對 4 次」與分數 | 3 分鐘 5 回合是規則核心，主持無法帶節奏 |
| 4 | 主頁先有分數 | idle 已顯示「目前分數 120」 | 未開局就有分，summary 的總分失去重量 |
| 5 | 候選機率外露 | result_retry 顯示 52% / 43% | 對小朋友是噪音；對評審是自曝不確定 |
| 6 | 字級不統一 | 標題級差三倍 | 視線落點浮動，遠處看像不同設計 |
| 7 | 圖示語言混用 | 線稿、實心並存 | 工藝分扣分點 |
| 8 | 顏色不承載資訊 | 頂欄永遠深綠 | 人多時失去最快的識別通道 |
| 9 | 無中途離場 | 只有 error 有回主頁 | 玩家走開即卡死，下一組無法開始 |
| 10 | 文案層級扁平 | 標題／指令／說明同一級 | 玩家不知要「睇」還是要「做」 |

**最關鍵是第 1 條。** 不改硬件、不改模型，只改畫面順序：AI 先判 → 隱藏 → 玩家投桶 → 揭曉。

## 3. 畫面規格（11 屏）

| # | Frame | 主標（H1） | 關鍵元素 | 備註 |
|---|---|---|---|---|
| 01 | home | 一起做分類小達人 | 兩按鈕（開始挑戰／分類圖鑑）、最高分 | 不顯示「目前分數」 |
| 02 | intro | 三個步驟 | 三格圖示、一句規則 | 3 分鐘 · 5 回合 |
| 03 | round_ready | 放件垃圾上鏡頭 | 回合、總倒數、物件狀態 pill | 3 秒自動拍攝 |
| 04 | capturing | 小偵探，睇清楚 | 相機框、3 秒倒數 | 框與中心 60% crop 對齊 |
| 05 | classifying | 你估會係邊一類？ | 進度條、一句「答案先收起」 | **不顯示類別** |
| 06 | await_bin | 投入個桶，蓋返個蓋 | 四格蓋狀態 | **新增元件**，感測值驅動 |
| 07 | verdict | 答對！／再試一次 | 你揀 vs AI、加分、連對 | 青檸頂欄＝正確、紅頂欄＝錯誤 |
| 08 | learning | 類別名 | 知識點一句、三個例子 | 頂欄轉類別色 |
| 09 | summary | 挑戰回顧 | 總分、答對數、最常錯類別 | 破紀錄才顯示「新紀錄」 |
| 10 | guide | 分類圖鑑 | 2×2 四格 | 由四欄改 2×2，字更大 |
| 11 | error | 相機未就緒 | 人話＋代號＋重試／回主頁 | 原設計缺「回主頁」 |

### 3.1 `await_bin` 的蓋狀態格（唯一新增元件）

- 四格等寬，每格 64×64 px（在 800×480 上約 120×120 px，實際按欄寬分配）。
- 開＝白底、灰框、空心方塊；關＝深綠底、青檸字。
- 哪一格由「開」變「關」：該格放大 1.2×、播「叮」，0.4 s 後進 verdict。
- 資料來源：`lid_mask`（感測值），**不是** `commanded`。

### 3.2 `verdict` 三種變體

| 變體 | 頂欄 | 圖示 | 加分 | 右格 |
|---|---|---|---|---|
| 正確 | 青檸 | ✓ 緣 | +100 起（含連對） | AI 判定（同玩家） |
| 錯誤 | 紅 | ✗ 紅 | +0 | **正解**（與玩家不同） |
| 逾時 | 灰 | ⌛ | +0 | 「沒有收到選擇」 |

## 4. 文案規則

| 層級 | 格式 | 例 |
|---|---|---|
| 指令（H1） | 動詞開頭，≤10 字 | 「放件垃圾上鏡頭」 |
| 說明（Body） | 一句，≤25 字 | 「蓋上嘅一刻，系統就知你揀咗邊個。」 |
| 知識（Learning） | 一句，≤40 字，含做法 | 「先清空、再沖洗、乾淨回收再造。」 |
| 錯誤 | 人話＋可行動＋代號 | 「請檢查相機排線，再按重試」＋E-02 |
