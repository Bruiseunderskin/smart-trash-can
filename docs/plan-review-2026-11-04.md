## 修正後的 Brief（此版本為準）

- 卡池 30 張不重複；**每局 5 回合，每回合 1 張**（澄清後）
- 3 分鐘一局；答對 +10、答錯 −5、未放入 0
- 無磁簧、無蓋位回授；VL53L0X 裝**桶身**只量物件下落
- 偵測到投入 → 3 s 關全部蓋；10 s 無投入 → 關蓋判該輪 0
- Korvo-1（S31）：相機 + LCD + 推理 + 語音 + 狀態機；GPIO 0 空閒
- S3-DevKitC-1：4×SG90（LEDC）+ 4×VL53L0X（XSHUT 改址）
- 板間 ESP-NOW；硬件除 4×ToF 外已齊（預算不是約束）

## 被否決的攻擊（附理由）

| 攻擊 | 否決理由 |
|---|---|
| HW-R22「板上是 OV3660」 | 錯。官方 `esp_cam_sensor` 支援表列 SC101IOT（1280×720 DVP YCbCr422）；esp32.com 的 S31-Korvo 日誌印 `Camera sensor handle ready: SC101IOT`。**但保留一點**：UYVY 與 YUYV 的 byte order 要拍一張相確認 |
| SW-R11 / HW-R24「S31 冇 PPA／2D-DMA」 | 錯。ESP-IDF 有 esp32s31 的 PPA 文件；PPA SRM 支援 `YUV422_UYVY` 輸入、`RGB565/RGB888` 輸出，內建 BT.601／BT.709。**保留**：輸出是 RGB 不是 BGR，channel order 與訓練／推論一致性要處理 |
| SW-R9「float32 權重超過 PSRAM」 | 數字錯。Korvo-1 模組是 16 MB PSRAM（非 8 MB）。但記憶體與延遲預算仍要寫 |
| SW-R29「永遠答對、−5 不可達」 | 前提錯。四個蓋一齊開，由玩家選桶，所以答錯可達。**保留**：報告需要 ground truth 標籤 |
| HW-R31（舵機電噪干擾 2.4 GHz） | 不是 must-fix，屬 T2 的量測項；但舵機線要遠離天線、用雙絞 |

## 最大單一風險

**VL53L0X 裝桶身只量下落**這件事本身：它是唯一決定分數的感測器，而幾何（FoV 25°、近距盲區、蓋板／手遮擋）到現在仍然只有假設、冇一張實測圖。其餘問題都是「改了就好」，這一項是「可能改了都做唔到」。

## 最該量的一個數字

四種材質（印刷啞面卡／全黑卡／鏡面卡／皺紙）× 20 次，用**真實幾何**（桶口下 8–15 cm）量：漏檢率、誤檢率、偵測延遲 p50／p95。呢個數字一出來，M2、M3、T5 三個爭議同時有答案。
