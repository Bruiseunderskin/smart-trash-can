# UI 流程重新設計（v2，2026-11-03）

狀態：**設計稿**，待拍板。作者：阿吉 the hermes。
取代對象：現有 `ui/lvgl` 的 9 狀態固定 demo 流程（`stc_ui.h` / `stc_ui.c`）。
前置：玩法走 **M1（投卡後自行閂蓋）**、感測改用 **磁簧／DRV5032**（見 `docs/lid-detect-research.md` v1.1）。

---

## 0. 三個關鍵改動（為甚麼要重畫）

| # | 舊 | 新 | 理由 |
|---|---|---|---|
| 1 | 首頁只有一顆 START | 首頁兩顆：**開始遊戲**／**認識分類** | 攤位需要「唔玩都可以學」的入口，亦是教育定位的門面 |
| 2 | AI 結果一出來就顯示類別 | **AI 先判，但結果隱藏**；玩家先投桶，之後才揭曉 | 一顯示答案，玩家照抄，遊戲即失去意義；隱藏後 AI 仍是唯一的正解來源 |
| 3 | 蓋的開合由系統自己講 | 由**感測器**回報，UI 顯示四蓋實際狀態 | 指令 ≠ 事實；`get_status` 目前回的是命令角度 |

## 1. 狀態表（11 個）

| # | 狀態 | 畫面內容 | 進入條件 | 離開 |
|---|---|---|---|---|
| 1 | `STC_HOME` | 標題「智分桶 EDU」、開始遊戲（大按鈕）、認識分類（次按鈕）、最高分 | 開機／結束後回主頁 | 開始→2；圖鑑→10 |
| 2 | `STC_INTRO` | 玩法三步圖示＋一句規則；「開始」 | 2 秒無操作不自動跳 | 開始→3；返回→1 |
| 3 | `STC_ROUND_READY` | 回合 n/5、總倒數 3:00、提示「請把卡放上掃描位」 | 每回合開始 | 卡偵測到／按掃描→4；超時→7(empty) |
| 4 | `STC_CAPTURING` | 相機預覽、3·2·1 圓環倒數、畫面提示「保持不動」 | 3 之後 | 拍完→5 |
| 5 | `STC_CLASSIFYING` | 進度動畫＋「AI 辨識中…」 | 4 之後 | 有結果→6；連續失敗→11 |
| 6 | `STC_AWAIT_BIN` | 「請投入其中一個桶並蓋上」＋**四蓋即時狀態**（開／關）＋倒數 10s | 5 之後 | 某蓋由開→關→7；10s→7(timeout) |
| 7 | `STC_VERDICT` | 大圖示（✓／✗）、**玩家選的桶 vs AI 判定**、+分、連對 | 6 之後 | 自動 1.5s 或按鈕→8 |
| 8 | `STC_LEARNING` | 正解類別、一句知識點、同類別其他例子縮圖、「下一回合」 | 7 之後 | →3（未完成 5 回合）／→9（完成） |
| 9 | `STC_SUMMARY` | 總分、正確率、最常判錯的類別、本機最高分、再玩一次／回主頁 | 第 5 回合結束 | →1／→重設→3 |

| 11 | `STC_ERROR` | 錯誤碼＋可行動建議（重試／回主頁） | 相機或模型失敗 | 重試→3 |

舊狀態對照：`RESULT_OK`／`RESULT_RETRY` → **`STC_VERDICT`**（正確／錯誤只換圖示與顏色）；`CATEGORY_GUIDE` → `STC_GUIDE`；其餘保留。

## 2. 版面（800×480 橫向，rotation 0）

統一四區，任何狀態都唔跳位：

```
┌──────────────────────────────────────────────┐
│ TOPBAR  高度 56  ─ 左：回合/進度  右：倒數或分數 │
├──────────────────────────────────────────────┤
│                                              │
│ BODY    高度 320 ─ 主內容（最大字級 56）        │
│                                              │
├──────────────────────────────────────────────┤
│ ACTION  高度 104 ─ 主按鈕（最小觸控 88×88）      │
└──────────────────────────────────────────────┘
```

- 字級沿用現有資產：`stc_font_tc_26/32/56/112`、`stc_font_num_32/80`。主標 56、內文 32、輔助 26、分數 80/112。
- 顏色隨類別變（可回收 #1F6FEB／廚餘 #E08B2A／有害 #C0392B／其他 #6B7280），**TOPBAR 亦跟隨**，玩家遠處都知現在講邊類。
- 四蓋狀態元件：四個 64×64 方格，開＝空心、關＝填色；哪個蓋被關上，該格 0.2s 閃一次。玩家一眼知系統有無睇到。

## 3. 每屏規格

### 3.1 `STC_HOME`
- 標題 56pt 居中偏上；副題 26pt「AI 垃圾分類教育遊戲」。
- 左大按鈕「開始遊戲」（180×88，主色）；右次按鈕「認識分類」（180×88，外框）。
- 右下角 26pt：`最高分 1,240`。
- 底部 26pt 跑馬燈式一句：「3 分鐘 · 5 回合 · 認得四類就贏」。

### 3.2 `STC_INTRO`
- 三個圖示橫排：① 放卡上掃描位 → ② 投入你認為正確的桶 → ③ 蓋上蓋子。
- 一句話規則 32pt：「AI 先睇，你後揀；錯都有解釋。」
- 主按鈕「開始」；左上返回。

### 3.3 `STC_ROUND_READY`
- TOPBAR 左「第 2 / 5 回合」，右「02:41」倒數（`stc_font_num_80`）。
- 中央：虛線框 240×180（掃描位示意）＋ 32pt「請把卡放上掃描位」。
- 若卡片偵測（未來）／3 秒無動作：自動進 `CAPTURING`；亦可以有「掃描」按鈕俾人手動觸發（示範時可控）。
- **注意**：現階段沒有卡片存在感測，預設 3 秒自動拍照，避免現場卡死。

### 3.4 `STC_CAPTURING`
- 全屏相機預覽（SC101IOT 1280×720 → 裁中央 800×480 顯示）。
- 中央 3·2·1 大數字（112pt），下方 26pt「保持不動」。
- 取景框四角標記，提示卡片要入框（配合中心 60% crop 的模型輸入習慣）。

### 3.5 `STC_CLASSIFYING`
- 中央 32pt「AI 辨識中…」＋進度環；**不顯示任何類別**。
- 若 p95 83.8 ms（S31 實測），此屏基本上閃一下就過——保留 0.6s 最短停留，否則玩家覺得「冇做過嘢」。

### 3.6 `STC_AWAIT_BIN`（新）
- 主標 56pt：「請投入其中一個桶並蓋上」。
- 中央：四個桶圖示橫排（可回收／廚餘／有害／其他），每個下面一個蓋狀態燈：開＝空心圓、關＝實心。
- 右下 26pt 倒數「10s」；5s 未動作時文案變「把卡放入桶，然後蓋上蓋」。
- 蓋關上的瞬間：該桶圖示放大 1.2×、播「叮」；0.4s 後進 `VERDICT`。
- 兩個蓋同時關 → 取**先關**那個，另一個記為 `double_close` 事件（存入 log，供日後分析）。
- 逾時 → `VERDICT` 顯示「沒有收到選擇」，該回合 0 分，仍進 `LEARNING`（教育優先，不跳過解說）。

### 3.7 `STC_VERDICT`
- 左半：玩家選的桶（大字類別名＋顏色）。
- 右半：AI 判定的類別＋信心值（26pt，如 `0.87`）。
- 中間大圖示：✓（正確）／✗（錯誤）／⌛（逾時）。
- 分數：`+100`／`+0`，連對 `×3` 用 80pt。
- 停留 1.5s 自動前進，亦可按「睇解說」立即前進。

### 3.8 `STC_LEARNING`
- 上方：正解類別色帶＋類別名（56pt）。
- 中段：一句知識點（32pt，≤40 字），例：「紙盒要先倒乾淨、壓扁，先算可回收。」
- 下方：同類別 3 個小圖（每個 96×96）＋「這就是同類」。
- 主按鈕：`下一回合` 或（第 5 回合）`看成績`。

### 3.9 `STC_SUMMARY`
- 大字總分（112pt）＋「5 回合 · 正確 3」。
- 三行統計：正確率、最常判錯的類別、本機最高分（破紀錄時加「新紀錄！」）。
- 兩個按鈕：`再玩一次`、`回主頁`。
- 底部 26pt：「拎住張卡，去真正嘅回收桶試下。」

### 3.10 `STC_GUIDE`
- 四欄（每欄 190px 寬），每欄：類別色塊＋名稱（32pt）＋2 行說明＋3 個例子。
- 左右箭頭切換（若有更多內容），右下「返回」。
- 這頁是「唔玩都可以學」的證據，報告／展板會截圖。

### 3.11 `STC_ERROR`
- 錯誤碼（26pt mono）＋人話（32pt）＋可行動（「請確認相機線」／「按重試」）。
- 兩個按鈕：`重試`、`回主頁`。

## 4. 轉移條件與計時（實作規格）

| 轉移 | 條件 | 逾時 |
|---|---|---|
| HOME→INTRO | `STC_ACTION_START` | — |
| INTRO→ROUND_READY | `STC_ACTION_START` | — |
| ROUND_READY→CAPTURING | 3 s 自動／手動 | — |
| CAPTURING→CLASSIFYING | 倒數完 | 3 s |
| CLASSIFYING→AWAIT_BIN | 有信心值 | 3 s 失敗→ERROR |
| AWAIT_BIN→VERDICT | 任一邊緣 `開→關` | 10 s → 逾時判定 |
| VERDICT→LEARNING | 1.5 s 自動 | — |
| LEARNING→ROUND_READY | `round < 5` | — |
| LEARNING→SUMMARY | `round == 5` | — |
| SUMMARY→HOME | 按鈕 | — |
| 任意→HOME | 長按 1.5 s（防誤觸離場） | — |

**比分規則**：正確 +100；連對第 2 次起每次 +20 加成（上限 +60）；逾時或錯 0 分、連對歸零。
5 回合滿分 500（100×5）＋最多 +180 連對加成。

## 5. payload 變更（`stc_payload_t`）

| 欄位 | 型別 | 說明 |
|---|---|---|
| `state` | `stc_state_t` | 11 個狀態 |
| `category_id` | `int8_t` | **AI 判定**（不是玩家選擇） |
| `confidence` | `float` | AI 信心 |
| `candidates[2]` | `int8_t` | 前二候選（解說頁可用） |
| `player_bin` | `int8_t` | −1 未選；0–3 玩家投入的桶 |
| `lid_mask` | `uint8_t` | bit0–3 即時蓋位（感測值） |
| `lid_event` | `uint8_t` | 最近一次 開→關 的桶號，0xF = 無 |
| `result` | `enum` | `OK / WRONG / TIMEOUT / ERROR` |
| `score` | `uint16_t` | 累計分 |
| `streak` | `uint8_t` | 連對 |
| `round` / `rounds_total` | `uint8_t` | 回合 |
| `time_left_ms` | `uint32_t` | 總倒數 |
| `high_score` | `uint16_t` | 本機最高分（NVS） |

## 6. 桌面預覽的按鍵對應（`ui/lvgl/preview`）

現有按鍵 1–9、M、R 保留並擴充：

| 鍵 | 動作 |
|---|---|
| `S` | 開始遊戲 |
| `1`–`4` | 模擬第 1–4 個桶「蓋上」（觸發 `lid_event`） |
| `G` | 開圖鑑 |
| `N` | 下一回合 |
| `R` | 重試／重新開始 |
| `M` | 減少動畫（保持現有） |
| `Esc` | 長按回主頁 |

> 這樣評審想看哪一步就按哪個鍵，不必等自動流程跑完；亦方便錄影時精準對位。
