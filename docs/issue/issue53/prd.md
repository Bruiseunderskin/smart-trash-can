# 整機整合 PRD

讀者：產品負責人、實作者及測試者。何時讀：決定實作範圍及驗收前。

## 問題與目標

把現有獨立的 UI、影像分類、遊戲和桶蓋介面接成離線流程：相機幀 → 160×160 前處理 → YOLO／ESP-DL int8 推理 → 模型標籤映射 → 遊戲 → UI 和桶蓋。單蓋／四蓋行為尚待釐清。先以 host 重播證明邏輯，再用可編譯的 S31 相機及 USB CDC S3 節點準備上板；實物表現由硬件持有人測量。

## 使用與行為

- 小朋友開始遊戲、拍攝物件，看到分類及學習資訊，完成五回合並看到總結。
- 低信心或影像錯誤時顯示重試；不確定結果不得開錯蓋。
- 遊戲回合不能切入 CHAT；遊戲分數只由遊戲核心持有。
- GAME 分類不依賴網絡；模式、相機、桶蓋與 UI 經契約互動。
- 無法連接節點時標記故障；loopback 僅為軟件測試，不能視為實蓋動作。

## 類別與固定桶位

| 模型 index | 標籤 | 桶位 |
|---|---|---|
| 0 | food | 1 廚餘 |
| 1 | hazardous | 2 有害 |
| 2 | other | 3 其他 |
| 3 | recyclable | 0 可回收 |

現有 `labels.txt` 為上述順序，`contracts/model/classes.json` 尚未對齊；啟動時須驗證順序，失配拒絕啟動。`data/field-probe` 是獨立測試集，不用於訓練、校準或閾值選擇。

現有 YOLO11n-cls 訓練所得 S31 `.espdl` 是目標模型，詳見 [模型交接](model-handoff.md)。

## 邊界

以 issue #53 的 D1–D7、介面和 I0–I7 為需求來源。只按其授權修改兩份契約；不重訓、換模型、改上游語音、重畫 UI、接後備 chat server，亦不實作 codec、SD 或 ESP-NOW。相機及 CDC 節點是指定硬件工作；其可編譯不等於實機可用。設計以 Figma 和現有 UI 規格為準，角色為綠豆。

## 成功條件

host 的映射、前處理、模式、遊戲、畫面接線及端到端測試有可重現證據；target 可編譯並保存建置紀錄。實機相機、螢幕、通訊、舵機、ToF、斷網和延遲各自留原始證據，未測不填結果。完整門檻見 [驗收](acceptance.md)，矛盾未處理前不要聲稱完整可執行。
