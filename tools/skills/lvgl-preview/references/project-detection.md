# Project detection

The preview scripts support native desktop LVGL projects that expose a simple SDL display initialization call. They are intentionally conservative: an ambiguous match is an error, not a reason to guess.

## Inspect first

Check, in this order:

1. `CMakeLists.txt`, `meson.build`, `platformio.ini`, or the project build wrapper.
2. LVGL version from the submodule, package manifest, `lv_version.h`, or dependency lock file.
3. Display creation and flush backend. The bundled script currently targets a call shaped like `sdl_hal_init(width, height)`.
4. Color depth from `LV_COLOR_DEPTH` or the project’s equivalent.
5. The native executable produced by the build.

## Supported default layout

The fixture and the original simulator use:

```text
project/
├── CMakeLists.txt
├── lv_conf.h
├── src/main.c
├── build/
└── bin/main
```

Pass `--main-file`, `--config-file`, `--build-dir`, and `--executable` when a project uses different locations. Paths must remain inside the project root. The script does not search dependency directories, `.git`, build trees, or `.lvgl-preview` state.

## Unsupported without an adapter

- Embedded-only projects with no native simulator executable.
- LVGL MicroPython, Emscripten, Unity, or browser backends.
- Projects whose display size is generated by a configuration system rather than a source call and `LV_COLOR_DEPTH` definition.

For those cases, keep the canonical skill and add a narrowly scoped backend adapter or use the project's documented simulator directly. Do not weaken the hardware boundary.
